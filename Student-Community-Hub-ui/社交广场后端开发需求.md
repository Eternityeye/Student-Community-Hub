# 社交广场模块后端开发需求文档

## 概述
本文档描述了社交广场模块的后端接口需求和数据库表设计。该模块实现了类似小红书/微博的社交帖子功能，包括发帖、评论、点赞、举报等功能。

## 数据库表设计

### 1. 帖子表 (social_post)

```sql
CREATE TABLE `social_post` (
  `post_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '帖子ID',
  `user_id` bigint(20) NOT NULL COMMENT '用户ID',
  `content` text NOT NULL COMMENT '帖子内容（富文本HTML）',
  `images` varchar(2000) DEFAULT NULL COMMENT '图片地址，多个用逗号分隔',
  `tags` varchar(500) DEFAULT NULL COMMENT '标签，多个用逗号分隔',
  `like_count` int(11) DEFAULT 0 COMMENT '点赞数',
  `comment_count` int(11) DEFAULT 0 COMMENT '评论数',
  `status` char(1) DEFAULT '0' COMMENT '状态（0正常 1已删除 2已屏蔽）',
  `create_by` varchar(64) DEFAULT NULL COMMENT '创建者',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` varchar(64) DEFAULT NULL COMMENT '更新者',
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  PRIMARY KEY (`post_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社交帖子表';
```

### 2. 评论表 (social_comment)

```sql
CREATE TABLE `social_comment` (
  `comment_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '评论ID',
  `post_id` bigint(20) NOT NULL COMMENT '帖子ID',
  `user_id` bigint(20) NOT NULL COMMENT '用户ID',
  `parent_id` bigint(20) DEFAULT NULL COMMENT '父评论ID（回复评论时使用）',
  `reply_to_user_id` bigint(20) DEFAULT NULL COMMENT '回复的用户ID',
  `content` text NOT NULL COMMENT '评论内容',
  `images` varchar(1000) DEFAULT NULL COMMENT '评论图片，多个用逗号分隔',
  `status` char(1) DEFAULT '0' COMMENT '状态（0正常 1已删除）',
  `create_by` varchar(64) DEFAULT NULL COMMENT '创建者',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` varchar(64) DEFAULT NULL COMMENT '更新者',
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`comment_id`),
  KEY `idx_post_id` (`post_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_parent_id` (`parent_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社交评论表';
```

### 3. 点赞表 (social_like)

```sql
CREATE TABLE `social_like` (
  `like_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '点赞ID',
  `post_id` bigint(20) NOT NULL COMMENT '帖子ID',
  `user_id` bigint(20) NOT NULL COMMENT '用户ID',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`like_id`),
  UNIQUE KEY `uk_post_user` (`post_id`, `user_id`),
  KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社交点赞表';
```

### 4. 举报表 (social_report)

```sql
CREATE TABLE `social_report` (
  `report_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '举报ID',
  `post_id` bigint(20) NOT NULL COMMENT '帖子ID',
  `user_id` bigint(20) NOT NULL COMMENT '举报用户ID',
  `reasons` varchar(500) NOT NULL COMMENT '举报原因，多个用逗号分隔',
  `description` varchar(1000) DEFAULT NULL COMMENT '详细描述',
  `status` char(1) DEFAULT '0' COMMENT '处理状态（0待处理 1已处理 2已驳回）',
  `handle_by` varchar(64) DEFAULT NULL COMMENT '处理人',
  `handle_time` datetime DEFAULT NULL COMMENT '处理时间',
  `handle_result` varchar(500) DEFAULT NULL COMMENT '处理结果',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`report_id`),
  KEY `idx_post_id` (`post_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社交举报表';
```

## API接口设计

### 基础路径
所有接口的基础路径为：`/social`

### 1. 帖子相关接口

#### 1.1 查询帖子列表
- **接口地址**: `GET /social/post/list`
- **请求参数**:
  ```json
  {
    "pageNum": 1,
    "pageSize": 10,
    "userId": null,  // 可选，查询指定用户的帖子
    "tags": null     // 可选，按标签筛选
  }
  ```
- **返回数据**:
  ```json
  {
    "code": 200,
    "msg": "查询成功",
    "rows": [
      {
        "postId": 1,
        "userId": 1,
        "userName": "张三",
        "userAvatar": "头像URL",
        "content": "帖子内容HTML",
        "images": ["图片1", "图片2"],
        "tags": ["标签1", "标签2"],
        "likeCount": 128,
        "commentCount": 45,
        "isLiked": false,  // 当前用户是否点赞
        "createTime": "2026-03-11 10:30:25",
        "comments": []  // 最新3条评论
      }
    ],
    "total": 100
  }
  ```

#### 1.2 查询帖子详情
- **接口地址**: `GET /social/post/{postId}`
- **返回数据**: 同上单个帖子对象

#### 1.3 发布帖子
- **接口地址**: `POST /social/post`
- **请求参数**:
  ```json
  {
    "content": "帖子内容HTML",
    "images": ["图片1", "图片2", "图片3"],
    "tags": ["标签1", "标签2"]
  }
  ```
- **返回数据**:
  ```json
  {
    "code": 200,
    "msg": "发布成功"
  }
  ```

#### 1.4 删除帖子
- **接口地址**: `DELETE /social/post/{postId}`
- **返回数据**:
  ```json
  {
    "code": 200,
    "msg": "删除成功"
  }
  ```

- **接口地址**: `POST /social/report`
- **请求参数**:
  ```json

    "reasons": ["违法违规内容", "虚假信息"],
  ```


- **业务逻辑**:

  - 可以在Redis中存储：`report:user:{userId}:date:{date}` 作为计数器

## 业务逻辑说明

### 1. 点赞功能
- 点赞时需要：
  1. 在 `social_like` 表中插入记录
  2. 更新 `social_post` 表的 `like_count` 字段 +1
- 取消点赞时需要：
  1. 删除 `social_like` 表中的记录
  2. 更新 `social_post` 表的 `like_count` 字段 -1
- 查询帖子列表时，需要关联查询当前用户是否点赞过（`isLiked` 字段）

### 2. 评论功能
- 添加评论时需要：
  1. 在 `social_comment` 表中插入记录
  2. 更新 `social_post` 表的 `comment_count` 字段 +1
- 删除评论时需要：
  1. 更新 `social_comment` 表的 `status` 字段为 '1'
  2. 更新 `social_post` 表的 `comment_count` 字段 -1
- 查询评论时需要关联查询用户信息（用户名、头像）

### 3. 举报功能
- 使用Redis存储用户每日举报次数
- Key格式：`report:user:{userId}:date:{yyyyMMdd}`
- 每次举报前检查计数，超过5次则拒绝
- 举报成功后计数器 +1，设置过期时间为当天结束

### 4. 权限控制
- 删除帖子：只能删除自己的帖子，或管理员可以删除任何帖子
- 删除评论：只能删除自己的评论，或管理员可以删除任何评论
- 举报：需要登录用户

## 已有接口复用

### 1. 文件上传接口
- **接口地址**: `POST /common/upload`
- **说明**: 已存在的通用文件上传接口，用于上传帖子图片和评论图片

### 2. 用户信息接口
- **接口地址**: `GET /system/user/profile`
- **说明**: 获取当前登录用户信息

## 注意事项

1. 所有接口都需要进行用户身份验证（除了查询接口可以考虑允许游客访问）
2. 富文本内容需要进行XSS过滤，防止脚本注入
3. 图片URL需要进行验证，确保是系统上传的图片
4. 评论和帖子内容需要进行敏感词过滤
5. 建议对帖子列表接口进行缓存优化
6. 点赞和评论数的更新建议使用数据库事务保证一致性
7. 举报功能的每日限制建议使用Redis实现，提高性能

## 开发建议

1. 使用MyBatis-Plus简化CRUD操作
2. 使用Redis缓存热门帖子列表
3. 使用消息队列异步处理点赞、评论等操作（可选）
4. 实现软删除机制，不直接删除数据
5. 添加适当的索引优化查询性能
6. 实现分页查询，避免一次性加载过多数据
